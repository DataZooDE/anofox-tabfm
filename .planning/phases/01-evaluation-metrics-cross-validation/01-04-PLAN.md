  <name>Task 1: Decide CV implementation shape — SQL table macro vs C++ TableFunction</name>
  <decision>Which implementation shape backs tabfm_cross_validate: a SQL table macro (composing query(...) per fold) or a C++ TableFunction (executing k predict+metric sub-queries)?</decision>
  <context>
    01-RESEARCH.md Open Question 1 / Assumption A5 flag an unresolved architectural fork: DuckDB SQL
    table macros cannot loop over k. CONTEXT.md's locked decision names tabfm_cross_validate as a
    "macro" and the file as src/tabfm_crossval.cpp (macro-module, analog src/tabfm_macros.cpp). This
    is a one-way door — the chosen shape dictates the module's entire structure, so it is gated before
    any building. Executor MUST spike the macro approach FIRST (per research recommendation): confirm
    whether a table macro body can build a per-fold UNION ALL via query('FROM ' || data) composition
    plus a generate_series/lateral fold expansion, producing per-fold rows + an aggregate row, WITHOUT
    C++-side loop execution, in DuckDB 1.5.4. Deviating from the locked "macro" decision requires
    explicit user approval.
  </context>
  <options>
    <option id="sql-table-macro">
      <name>SQL table macro (preferred, honors CONTEXT.md)</name>
      <pros>Matches the locked "macro" decision and src/tabfm_crossval.cpp module shape; lower code volume; reuses the existing classify/regress query() composition pattern</pros>
      <cons>Depends on query() inside a table macro being unrestricted in DuckDB 1.5.4; fold expansion must be expressed without a C++ loop</cons>
    </option>
    <option id="cpp-tablefunction">
      <name>C++ TableFunction fallback</name>
      <pros>Full control over the k-fold loop and sub-query execution; no reliance on macro query() behavior</pros>
      <cons>Deviates from the locked "macro" decision (needs user approval); more code; changes the module shape from macro-module to table-function module</cons>
    </option>
  </options>
  <resume-signal>Reply "macro" to proceed with the SQL table macro, or "tablefunction" (with approval to deviate from the locked decision) to use the C++ fallback.</resume-signal>
